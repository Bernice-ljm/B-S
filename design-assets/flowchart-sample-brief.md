# 流程图样图 brief

## 图示范围

- 图名：审批申请——从提交到可追溯终态
- 位置：中期设计报告“复杂流程实现设计”章节
- 画布：A4 正文通栏，170 mm × 85 mm
- 形式：可编辑 SVG；另导出 PNG 预览与 PDF

## 组件与职责

| 组件 | 标签 | 职责 | 属性 |
|---|---|---|---|
| 申请端 | 提交申请 | 提交经服务端校验的申请数据 | existing |
| 流程解析 | 冻结审批快照 | 固定模板版本、节点顺序、规则与实际审批人 | new / 设计亮点 |
| 待办生成 | 生成首个待办 | 激活第一个审批节点并通知审批人 | existing |
| 审批节点 | 当前节点审批 | 当前实际审批人批准或驳回 | existing |
| 后续流转 | 下一节点 | 生成后续待办并回到节点审批 | existing |
| 通过终态 | 已通过 | 所有节点批准后的终态 | existing |
| 驳回终态 | 已驳回 | 当前节点驳回后的终态 | existing |

## 主路径与次要流

1. 申请端将经校验的申请提交给流程解析。
2. 流程解析冻结审批路径与人员快照。
3. 系统生成第一个待办。
4. 当前节点审批，根据结果进入下一节点或终态。
5. 仍有后续节点时生成下一节点，并以虚线反馈回当前节点审批；虚线在本图中仅表示“循环回到同类审批步骤”。

底部说明条表达事务一致性边界：申请状态、待办、审批日志和通知事件一致提交。

## 视觉主张

读者从左向右阅读；“冻结审批快照”是唯一饱和强调色，突出本项目的可追溯设计。通过和驳回使用浅色填充，同时用文字和路径标签表达语义，不只依赖颜色。

## 样式假设

- 报告按 A4 页面排版，流程图使用正文通栏宽度。
- 中文字体首选 Microsoft YaHei，回退为 Noto Sans CJK SC、Arial、sans-serif。
- 白底、深色正文、无渐变、无阴影，适合打印和 PDF 阅读。
- 普通字号按课程报告阅读距离设置为 7.5–9.5 pt，标题 13 pt。
- 本图只展示主审批流，不展示草稿编辑、撤回及复制重提，以控制信息密度。

## 图注草案

**图 X　申请提交与顺序审批流转。** ①申请通过服务端校验后提交；②系统按提交时配置解析审批规则，并冻结模板版本、节点顺序和实际审批人；③创建首个待办；④当前节点审批后，若仍有后续节点则生成下一待办并继续顺序审批，最后一个节点批准后进入已通过终态，任一节点驳回后进入已驳回终态。申请状态、待办、审批日志和通知事件在同一事务边界内保持一致。
